New in this proposal

  • P1 hourly_summary: no feed line and no comparison chip; the Traffic hour drawer gains "What the tablet reported": its counts per trigger and outcome, its dropped reports and its process deaths.
  • P2 runtime_transition: "Sync process · died" failed line that opens an incident, other changes neutral; owned by Traffic.
  • P3 native cycle_report: "Sync cycle · failed while sending", and a stage timeline in the drawer; a stage outside the four is shown as stored.
  • P4 Silence, computed when Activity reads: "Tablet silent · since 11:56" failed line; once a report arrives it reads "Tablet was silent · 1 h 8 min". No incident, no stored event.
  • P5 Bridge closed: "Bridge closed" System line; "Bridge started" says how long Bridge was off, or that it did not close normally.

Not proposed

  • MCP status and per-kind coverage changes: they have no screen.
  • Host or remote address capture on reports: undecided by the owner, so no field shows it.
  • Non-failed cycle_report lines: still decided against (they flood the feed).
  • "Bridge off" bands in the feed or chart: the chart's hatched slot stays "No activity".
  • Notifications or toasts for the silence alarm.

P2 · runtime_transition lines Proposal · $$$$

Owner: Traffic. The design places every mobile report under Traffic ("Failed reports only, under Traffic"), and System is the section for Bridge's own starts, warnings and errors that no other type owns. A transition is a report the phone sends about itself, so Traffic owns it. Its failure still surfaces while Traffic is off, through Traffic's red chip. A death of the sync process is a failed line; every other change (sync process started, main service started) is a neutral line, which the failure switch skips. Mobile reports a death per event only for sync; deaths of main are counted in the hourly summary. The row reads the stored process and subject, then the stored transition; a value mobile has not defined is shown as stored. The row time is when it reached Bridge; the drawer shows the time on the tablet and the late arrival with the existing amber chip. A death opens no incident, so the drawer has no "Around it" and no "kept until".

P3 · Native cycle_report, failed Proposal · $$$$

Today the row reads "Sync cycle" followed by the stored outcome. Proposal: the detail names the stage it failed at, in plain words from a closed enum: failed as it started (attempt started), failed while claiming changes, failed while sending, failed while applying. The drawer draws the four stages with the run-story timeline: green for the stages it passed, red where it stopped, gray "Not reached" after. It shows no times per stage, because the report stores none. The stage is the stored previous_cycle.last_stage (attempt_started, claim_ops, http, apply_write); any other stored stage reads "failed while" and the stage as stored, and the drawer shows "Stopped at" with that value and no four-step bar. A failed cycle without a stage keeps today's "failed". The cause box is the incident's recorded cause, previous_cycle.error_cause. A cycle report carries no phone time, so "When" has only its arrival. Only failed cycles get a line (non-failed ones still flood the feed).

P4 · Tablet silence, computed when read Proposal · $$$$

Activity and the MCP compute it each time they read: no watcher, no timer, no background process, no incident and no stored silence event. A silence is 60 minutes or more in which Bridge received no report from the tablet while Bridge was on. Owner: Traffic, origin Bridge: it is about the phone's reports, but Bridge reads it. It is a failed line, so it counts in Traffic's red chip. Heard is the receipt time of any stored report of the device, minute precision while its reports are retained; past that, the hour of its hourly_summary, hour precision. The silence counts only time Bridge was on: it starts at the later of the last report received and the Bridge start, and it never spans a period where Bridge's own state is unknown: after a start with no recorded close, it ends at the last row Bridge wrote before that start. Example: Bridge closed at 23:46, the tablet's last report was received at 23:40, Bridge started at 08:58 and received a report at 09:00. The silence could start only at 08:58, so there is none. While silent the row reads "since 11:56"; once a report is received it reads how long.

P5 · Bridge closed Proposal · $$$$

A clean shutdown writes one event. It shows as a System line "Bridge closed", grouped per hour like every System line. The next "Bridge started" line pairs with it: its detail reads "off 9 h 12 min". A start with no clean close before it reads "did not close normally" in plain muted text, not red: a power cut or a kill is not a failure Bridge can prove, and red is spent only on failures. The chart keeps its "No activity" hatch; it still draws no "Bridge off" band.
