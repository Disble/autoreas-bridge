What happens to a notification

Three verbs the user controls, and one they never get. Each keeps its own timestamp, so they compose instead of overwriting each other.

Have I seen it?

Unread

Where every record starts. Counted in the rail badge.

Read

Set by opening the detail, or by hand. Reversible — “mark unread” puts it back.

Stop bothering me — a layer, not a state

Dismissed

Closes the toast and stops future attention for that record. It does not mark it read, and it does not take it out of the inbox. That is why dismissal carries its own timestamp rather than reusing the read one — a record can be dismissed and still unread.

Deal with it later

Archived

Off the Active list, still searchable. Marks it read if it was not. Nothing is destroyed.

Restored

Back on the Active list. Deliberately does not make it unread again — you already saw it.

There is no delete

Dismissing an interruption and erasing what happened are different intentions. The UI offers the first; only retention ever removes a row, and it will not touch one that is still unread or still actionable.

Restarting changes nothing

Read, dismissed and archived all live in SQLite, so closing the app is not a way to clear the badge. Startup re-reads the same rows and does not replay the backlog as toasts.
