# Apply Progress: SDD-74 Mobile Covers

## Delivery mechanics (orchestrator decision, 2026-09-14)

`tools/checksdd` runs on every commit that touches `*.go`. It requires the active change (`.atl/active-sdd-change`) to have every task checked and a passing `verify-report.md`, so a mid-change work-unit commit cannot pass the gate honestly.

Each work unit is therefore closed as an **index tree checkpoint** instead of a commit:

- stage the unit, verify it, then run `git write-tree`;
- keep the tree reachable with `refs/sdd74/<wu>-tree`.

After final verification writes a passing `verify-report.md`, the orchestrator replays the checkpoints in order (`git read-tree <tree>` then `git commit`). The result is one commit per work unit, and each passes the real gate.

Precedent: SDD-28, SDD-71 and SDD-73 committed after verification. SDD-72's per-unit commits touched only frontend files, which the gate's `*.go` glob skips.

**Mutation scoping under cumulative staging.** `ditto staged` measures the index against HEAD. From WU2 on, pass `--exclude-prefix` for every earlier unit's files that the current unit does not modify, so each score judges only that unit's lines.
