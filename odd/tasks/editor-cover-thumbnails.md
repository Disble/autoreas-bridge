# Editor cover thumbnails

## Objective and scope
Show the saved cover (or the existing placeholder) beside each visible Library anime and beside the selected Editor title, as marked in the screenshot. Keep cover URLs/paths out of image elements; reuse the application's cover resolver. Do not add a live preview of the unsaved Cover source field. Leave unrelated untracked `.tmp-*` files alone.

## Constraints and approach
- Branch: `feat/editor-cover-thumbnails` (created from `main` before writing source).
- TDD: enabled by repository `AGENTS.md`; runner: `bun --cwd="frontend" run test -- <focused files>` for frontend, `go test -count=1 ./<owning-package>/` for Go. Follow RED → GREEN → MUTATE → REFACTOR where relevant.
- Library list is progressive. Gate lookups by a server-supplied cover-presence flag and only resolve rendered rows; respect the cover binding's concurrency limit. Preserve skeleton geometry and fallback on missing/failed covers.
- One writer at a time. Generated bindings via project command if bound Go types change; never edit `frontend/wailsjs/` directly. Keep generated files untracked.
- Initial authored diff estimate ~250–400 lines was low: ECT-2 now reports ~1422 authored lines across implementation and tests after a test-first cache correction. Delivery strategy: ask-on-risk; decide stacked-to-main or feature-branch-chain before any work-unit commit. Do not code-golf away tests to fit the heuristic.
- Commit policy: do not commit until explicit user authorization, despite work-unit commit guidance; report any pending commit as a closure blocker.
