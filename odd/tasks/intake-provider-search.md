# Intake — Find on provider

Objective: unblock an intake row the matcher could not resolve by searching the download providers from a modal and picking the page.
Branch: `feat/intake-provider-search` (worktree `autoreas-bridge-worktrees/intake-provider-search`, based on `fix/intake-checkbox-first`). Delivery: feature-branch-chain (assumed from the previous feature's choice). Runners: `go test` + ditto for Go, Bun/Vitest + Stryker staged for the frontend.

## Specs

- **S1 — Provider search port (backend).** Search every download provider by free text and return each page with its title, page URL and provider name. "este buscador incluiría a todos los proveedores, no solo JKAnime (de momento soloe está JKanime, así sería solo este ahorita)". The existing `NameSearcher` matching path keeps its behavior. Exposed to the frontend as one Wails method.
- **S2 — Pick resolves and rechecks the row.** Choosing a page resolves the row through the existing `ResolveMatch` and then rechecks availability for that row only, so it can become available without running matching again. User, on "should picking trigger the availability check": "1. Yo diría que sí, de una vez." Assumption: every manual resolve (the Ambiguous candidate buttons too) rechecks its row, since they share `ResolveSeasonMatch`.
- **S3 — Reuse the MAL modal's visual parts, separate logic.** "2. Entiendo, mejor separarlos en lógica, reutiliza la parte visual lo que puedas entonces. Recuerda que tenemos métrica de no duplicación de código que pasar." The MAL modal's behavior and tests stay unchanged.
- **S4 — Find on provider modal on blocked rows.** "mejorar estos bloqueos agregando el botón de Buscar el anime por un modal (arquitectura) al estilo de MAL". "que funcione como el de MAL, no compliques la vida": search while typing (300 ms debounce, minimum length), seeded from the row name on first open, select highlights, the primary button confirms. "esto no reemplaza al botón de MAL, solo afecta al workflow de JKanime." Scope (approved mockup, artifact "Intake — Find on provider"): a round icon button "Find on provider" beside Fetch metadata, only on rows whose status is Not found, Ambiguous or Search failed; results list every page the providers returned, ranked, as title plus "Provider · page URL"; confirm label "Use this page".
