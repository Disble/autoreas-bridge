# cfclearance: provider egress passes through the Cloudflare clearance transport
Objective: a new bounded context `internal/cfclearance` (hexagon) whose `http.RoundTripper` every provider adapter's `*http.Client` passes through, clearing Cloudflare managed challenges transparently through its own ports; wired at the composition root; ADR-029 mirrors stay as the last resort.

## Specs
- S1: "este módulo debe estar diseñado para ser conectado al módulo de providers, quienes tendrán que pasar de ahora en adelante por este módulo para pasar la validación de cloudflare para comunicarse con jkanime (el único provider de momento, si hubiera más también les aplicaría)". Acceptance: `cfclearance.Transport` implements `http.RoundTripper`, host-agnostic (state keyed by registrable domain); the composition root builds one shared `*http.Client` on it and injects it at the four jkanime construction sites (`internal/desktop/app_runtime_services.go:225`, `app_season_availability.go:128`, `app_startup_runtime.go:250`, `app_season_searcher.go:21`); a `tools/checkarchitecture` rule refuses `http.DefaultClient` and `&http.Client{` inside `internal/download/sites/**`, so a future provider cannot bypass the module; the `nil`/`DefaultClient` fallbacks inside `internal/download/sites/jkanime` remain untouched in this feature (they are the test seam) and the rule targets construction, not the fallback lines.
- S2: "Como la arquitectura hexagonal que es, no debería haber cambios gigantes en los módulos individuales sino que nos manejaríamoso por adaptadores y puertos." Acceptance: `git diff dev -- internal/download/sites` is empty; ports declared in `internal/cfclearance`: `Solver` (`Solve(ctx, origin, rejected string) (Clearance, error)`), `ClearanceStore` (`Load(domain) (Clearance, bool)`, `Save(domain, Clearance)`, `Delete(domain)`), `Publisher` (`Publish(events.Event)`); adapters: `webview2.ProcessSolver` (Windows), `UnsupportedSolver`, `MemoryStore`, `events.MemoryBus`; `internal/cfclearance/**` imports only stdlib, `golang.org/x/net/publicsuffix`, `autoreas-bridge/internal/events` and, in the `webview2` sub-package, `github.com/wailsapp/go-webview2` and `golang.org/x/sys/windows`; a depguard entry in `.golangci.yml` denies `internal/download`, `internal/season`, `internal/anime`, `internal/desktop` and `github.com/wailsapp/wails/v2` to `internal/cfclearance/**`.
- S3: "superar este bloqueo sin intervención del usuario, no requiere de solicitar programas de terceros, tampoco que el usuario deba proporcionar permisos especiales fuera de la app ni copiar ni pegar cookies de navegadores del usuario. Todo este proceso debe ser realizado de forma transparente al usuario por detrás." Acceptance: the solver child is the application's own executable relaunched with `--cfclearance-solve <origin> <rejected> <dataDir> <timeout>`, handled in `main.go` before `wails.Run`; the WebView2 window is created with `WS_POPUP` and `WS_EX_TOOLWINDOW|WS_EX_NOACTIVATE`, never shown, and the Windows-tagged test asserts it is never visible; no prompt, toast, setting or UI; the engine profile lives under `%LOCALAPPDATA%\autoreas-bridge\cf-webview2`; no runtime beyond the WebView2 runtime Wails already requires.
- S4: transport behaviour contract (from the approved blueprint, section 03 decision table). Acceptance, each pinned by a test: (a) unchallenged responses pass through byte-identical, no cookie and no User-Agent change; (b) a challenge is `403`/`503` with `Cf-Mitigated: challenge`, or a `2xx` `text/html` body carrying `just a moment` or `cf_chl_opt` (case-insensitive) within the first 64 KiB; a bare `403` is never a challenge; (c) one solve per registrable domain at a time, concurrent challenged requests share it; (d) at most `MaxSolvesPerRequest = 2` solves per request (stale stored clearance, then a fresh challenge) and at most `MaxConcurrentSolves = 1` solve process-wide; (e) only `cf_clearance` and `__cf*` cookies are stored and replayed; the caller's own cookie of the same name wins; (f) the replay sends the engine's User-Agent; a solver result without User-Agent or without a fresh `cf_clearance` is refused; (g) a rejected stored value is deleted and passed as `rejected` to the next solve; (h) a failed, timed-out (`SolveTimeout = 30s`) or unsupported solve returns the original challenge response unchanged and opens a `Cooldown = 10m` for that domain, during which no solve starts; (i) a request whose body is not replayable (`GetBody == nil` and body present) is never retried; (j) events `clearance.challenge_detected`, `clearance.solved`, `clearance.failed` are published with domain, duration ms, attempt and reason, and never a cookie value; (k) the User-Agent is stored before the cookies become visible (one lock), so no replay can carry a fresh cookie with the old User-Agent; (l) `Policy.Eligible(host)` defaults to every HTTPS host; an ineligible host passes through as (a).
- S5: quality gates from CLAUDE.md. Acceptance: `internal/cfclearance` is CORE: 100% of decisions covered and `ditto` ≥ 0.80 with every survivor killed or recorded as equivalent; `internal/cfclearance/webview2` is IMPORTANT: behaviour covered by a Windows-tagged test against a local `httptest` fixture whose page sets `cf_clearance` from JavaScript, plus the child protocol through a real child process; wiring files are INFRASTRUCTURE; every Go file ≤ 400 effective lines; English identifiers and comments; `gofmt`, `go vet`, `go run ./tools/checkgofilesize`, `go run ./tools/checkarchitecture`, `scripts/lint.ps1 -Profile all` green; ADR-030 under `docs/adr/`; `docs/architecture.md` gains the context in section 1; a "no wire change" note in `docs/openapi.yaml`'s changelog for the mobile consumers; `node scripts/log-lesson.mjs` appended with the non-obvious lessons.
