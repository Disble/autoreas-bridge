# Episode recognition triage PoC

## Objective and authorization
Build a disposable executable PoC that demonstrates deterministic multi-signal episode recognition on real folder observations and reproducible scenarios. User explicitly authorized immediate construction on 2026-10-10, before approving revised implementation ODDs. This is PoC tracking, not approval of the old four-ODD plan or production integration.

## Problem and rationale
The earlier design excluded useful chronology; the initial PoC then overcorrected with a global collection-convention gate, producing unresolved real results even when ordinary signals agree. The user confirmed their actual process in a mini-interview: filter watched using current progress and the established convention, resolve clear pending numbers despite date inversions, use defeasible elimination, and use chronology when numbers cannot resolve. No individual signal must prove universal standalone reliability. Preserve provenance, assumptions and conflicts without manufacturing uncertainty or numerical confidence weights.

## Scope
- Disposable Bun/TypeScript tool under `tools/episode-triage-poc/`, with a pure recognition function, a read-only filesystem observation adapter, reproducible cases and CLI.
- Standalone offline HTML report/demo exposing every proposed association, alternatives, source evidence and conflicts; generated by the same algorithm, not a second implementation.
- Real immediate-child media observations from the previously discussed Slime4, Mushoku III, Yani Neko and Date a Live III folders when uniquely available. Missing/ambiguous folders are reported, not replaced by arbitrary samples.
- Evidence-backed readme documenting exact rules, runnable commands, assumptions and results.
- Full self-contained contract and fixtures for fresh delegated models.

## Constraints and non-goals
- No AI in recognition; no network or dependency installation.
- No production app, database, notification, downloader cursor, Wails or frontend changes; no permanent media index or continuous watcher.
- No writes/renames/deletions in anime folders. Outputs only under `tools/episode-triage-poc/artifacts/`.
- Preserve pre-existing `.gitignore` modification, five historical untracked triage docs and obsolete task record.
- Do not infer content truth from label agreement. Do not treat Bridge cursor-derived labels/events as independent confirmation.
- Timestamp ties remain partial-order intervals, never lexically manufactured episode certainty.
- Collection conventions may be supplied, but are not a global permission gate. Local consecutive-pending hypotheses use observed progress, names, structure and dates with explicit provenance; count alone does not prove content identity. Fractional progress cannot be truncated into a next ordinal.
- Acquisition history is personal memory, not an observable weekly/copied classification. Reassigned folders and rewatches use current progress, never path provenance or canonical-format-alone as watched status.
- Duration anomaly notification is outside this recognition PoC. Optional ffprobe acquisition may collect duration/tags only, with unavailable/error represented explicitly; do not require it for recognition.
- All files remain <=500 effective lines; reduce genuine duplication, never remove evidence to meet a cosmetic budget.
- No commit, staging, push, or merge authorization. Work-unit commits remain pending an explicit user request; do not claim them.

## Public seam and concrete behavior
`analyze(snapshot)` is the reproducible public seam. Input contains observed entries, explicit collection assumptions and optional context; output contains per-entry candidates, conclusions, support, contradictions and pending-episode compatibility, without side effects.
- Use conservative deterministic token/marker/suffix grammar; no requirement that unseen title stems match renamed entries.
- Generate creation and modification order hypotheses plus folder/context constraints; preserve missing signals, intervals and conflicting hypotheses.
- Combine contextual evidence and global assignment consistency. A clear meaningful pending number is decisive over creation-order inversion in the user's normal workflow; chronology remains useful fallback. Do not require all signal families to agree or invent numerical confidence weights.
- Distinguish corroborated association, conditional inference, conflict and unresolved outcome. Publish exact decision rules in README and report.
- A stable file alone is not episode1; an explicit initial complete-prefix convention and compatible context can support conditional episode1.
- Ambiguous MULTI/FRACTIONAL/RANGE/SPECIAL claims are not collapsed to a trailing integer.
