# Preseason readiness

## Objective and scope
Fix historical Season truth and Today navigation, make first-watch date automatic, enrich Season intake one anime at a time before batch creation, and replace the uninformative quota meter. User approved implementation in a separate worktree on `feat/preseason-readiness` from `dev` (`bfff1d0`). The original checkout contains unrelated changes and must remain untouched. Preserve SQLite as the only anime owner; historical OpenSpec is evidence, not execution authority.

## Problem, decisions, and constraints
- A historical closed season in the shared store masquerades as an open one in Today/navigation. A historical rate action may be exposed too.
- `premieredAt` currently mixes an editor description of first air date with a first-watch timestamp; the user wants the first-watch date to be automatic and not editable. Existing undated progress must not be assigned a fabricated first-watch date; investigate exact evidence before any backfill.
- Historical Ordering currently reads live anime days/open-season data. Capture the actual ordering at **season close**, not only at Apply. Old closures lacking a snapshot must display an explicit unavailable state. The historical watching-pipeline live-section overlay needs the same integrity treatment.
- Season batch create currently carries no MAL metadata. Reuse explicit one-row search/confirm before batch create, persist per-row selection, then consume it at creation. No automatic batch network fan-out; manually entered values win.
- Quota is real but its historical meter duplicates Selection. Replace with an honest created-candidate selection outcome breakdown (approved/rejected/not yet graded), validated against the current decision rule.
- The verified fresh-worktree bootstrap rule is in `AGENTS.md` and `CLAUDE.md`: Bun/Vitest, frozen Bun install, Wails CLI, ignored `dist/.keep` and generated bindings, typecheck and lockfile check. Never run `node --test` on Vitest suites.
- TDD source: `AGENTS.md` frontend RED→GREEN→MUTATE→REFACTOR and Go strict mutation boundary. Runners: `bun --cwd=frontend run test -- <focused test>` and `go test -count=1 ./<owning-package>/`, plus owning Go staged `ditto` threshold 0.80. A delegated verify agent owns final verification; the parent runs the commit hook (no bypass). Theme skill and lean-tests apply.
